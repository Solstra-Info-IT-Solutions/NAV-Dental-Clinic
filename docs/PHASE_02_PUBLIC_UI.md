**Status:** Tested (locally against a production build; not deployed)

## 1. Objective and business value

Give patients a fast, accessible, brand-consistent website now: who the clinic is, where it is, and a one-tap way to call. This phase also sets up the foundation the booking, contact and admin phases plug into, with no fake features. Every button does something real today.

## 3. Architecture and decisions

| Decision | Detail |
|---|---|
| **Next.js 16.4.2 with Cache Components + Partial Prefetching** | The defaults from `create-next-app` for this version. Data functions use `"use cache"` + `cacheTag` + `cacheLife("hours")`, so Phase 3 can swap in MongoDB reads and admin edits can invalidate with `revalidateTag("clinic-settings" / "services")`. Every public page prerenders as static HTML. |
| Tailwind v4 via `@tailwindcss/turbopack` | No PostCSS config needed. `--color-*: initial` **removes Tailwind's default palette**, so only brand tokens compile. A stray `bg-blue-500` produces no CSS. |
| Settings behind `getPublicSettings()` | Pages never import constants directly. Phase 3 changes one function body. |
| Honest unconfigured states | No opening hours → "Please call to check timings". Online booking closed until hours exist → the appointment page says so and offers the phone number. WhatsApp hidden until confirmed. Credentials not rendered while empty. |
| Real 404s for services | `ensureStatic = "navigation"` on `services/[slug]` makes unlisted slugs render fully before responding, so unpublished or unknown services return **HTTP 404** rather than a streamed "soft 404" with status 200. No segment `loading.tsx` is used for the same reason (a Suspense fallback fixes the status at 200). |
| Native `<details>` FAQs | Accessible, no client JS. |
| Client JS limited to navigation | Only `NavLinks` (active state) and `MobileNav` (disclosure) are Client Components. |
| Provisional SVG logo | `components/layout/logo.tsx` and `app/icon.svg` are a hand-traced flat version of the mark, labelled provisional in code. The wordmark is set in Cinzel/Montserrat. The supplied render is used as the home hero image. |
| Legal pages | Drafts with a visible "Draft for clinic review" notice, **`noindex` while unapproved** (`legalPagesApproved: false`). |
| Security headers (baseline) | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `X-Robots-Tag: noindex` on `/admin` and `/api`, `poweredByHeader: false`. A nonce CSP comes in Phase 8. |

## 4. Key flows

- **Call:** every page has a `tel:+918006606001` link in the header (desktop), the sticky mobile action bar, CTAs and the footer.
- **Book:** "Request an appointment" / "Book" → `/appointment`, which shows the honest closed state with phone CTA until Phase 4 + configured hours enable the form.
- **Directions:** "Get directions" opens Google Maps searching the verified address text (no invented coordinates); a verified `mapUrl` overrides it.

## 6. Known issues / limitations

- `npm audit` (including dev dependencies) reports 5 **high** advisories in `braces`/`micromatch` pulled in by `eslint-config-next@16.4.2` (lint tooling only, not shipped to the browser or server). The only "fix" downgrades to `eslint-config-next@14`, which is incompatible. Recheck on the next Next.js patch.
- **The C: drive has ~10 MB free.** npm's cache and Playwright's browsers were redirected to D: for this work (`npm_config_cache=D:/.npm-cache`, `PLAYWRIGHT_BROWSERS_PATH=D:/ms-playwright`). Run E2E tests with `PLAYWRIGHT_BROWSERS_PATH` set the same way, or reinstall browsers after freeing space.
- Lighthouse not yet measured (Phase 8).
- Approach statements on `/about`, the "What you can expect" list on the home page, service copy and FAQ answers are **drafts needing clinic approval**.
- The error boundary (`app/(public)/error.tsx`) hardcodes the phone number because client error boundaries cannot read server settings.
